# 章节更新与目录刷新

当前为 ORSP 1.x 可选实验能力 `top.xxread:chapter-updates`，
[OEP-0005](../OEP-0005-chapter-updates.md) 是英文合同。现有搜索、详情、目录、正文端点保留。

## 怎样发现更新

`GET v1/books/{bookId}/updates` 返回作品 ID、`catalogVersion`、`chapterCount`，
有章节时包含 `latestChapter` 对象；实际更新时间已知时才返回 `updatedAt`。
目录版本是稳定的、不透明的字符串，只能比较相等与否，不是页码、时间或全局用户 ID。
每次新增、改字、改名、插入、重排、删除章节或更换 EPUB 原文件都必须改变目录版本。
没有变化的查询不能刷新版本或伪造更新时间。

目录的每一页返回同一个 `catalogVersion`，章节条目与正文均返回 `contentVersion`。
正文版本是实际返回 `content` 字符串 UTF-8 的 SHA-256：改同一章也能检测到，不能只看章数。
章节 ID 必须稳定，不能用当前顺序编号重新生成；重排不会把书签和段评绑到另一章。

## 更新拉取

1. 手动检查立即重新验证，自动检查按客户端周期进行；首次检查建立基线。
2. 状态没变化可返回 304，节省目录与正文传输；缓存有效不能冒充已经检查最新状态。
3. 版本变化后拉取完整目录，用 ID 区分新章/撤回，用正文版本区分改字。
4. 保留没变化的正文缓存、阅读位置、书签、批注；仅让变化章节的正文缓存失效。
5. 完整目录确认后再更新基线/消除更新提示；网络失败保留旧缓存并标记过期。

分页可带 `catalogVersion` 参数固定读取版本，正文端点同样支持。
源已变更且不能提供该版本时返回 409 `X_CATALOG_VERSION_CONFLICT`，客户端重新获取状态。
不同目录页的 HTTP ETag 本来就可以不同，不能用 ETag 相等判断整本书版本一致。
未声明能力的源不能发送新增参数，旧客户端继续用原目录接口刷新。

## EPUB 与后续实现

替换 EPUB 产生新的原文件身份和目录版本，必须保持旧文件/定位的版本关联。
无法确认新旧章节映射时不能把全部章节计为新增，也不能重置用户进度。
本地下载的正文仍走显式下载、合并与修订冲突处理，协议不强制静默覆盖本地编辑。

开元阅读当前已有手动检查和约 30 分钟的自动检查资格间隔，后台/不可见页面可能延后。
此次元创服务补齐最新目录、章节可靠时间和更新状态；新状态接口及逐章版本缓存优化
由支持扩展的客户端启用。不能把协议与服务更新说成已经发布了新的客户端。

结构见 [Schema](../schemas/chapter-updates.schema.json)，端点见
[OpenAPI](../chapter-updates.openapi.yaml)，检查命令：
`python scripts/validate_chapter_updates.py`。
