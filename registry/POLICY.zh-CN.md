# Registry 审核与下架参考政策

[English](POLICY.md)

## 适用范围

本文是提供给独立社区运营 ORSP Registry 时采用的政策模板。Origo X 项目不运营活动
Registry，也不接受书源收录投稿。采用者必须自行建立审核、权利投诉、安全和下架流程，
并不得把收录表述为对内容权属、安全性、永久可用性或质量的认证。

## 提交者声明

提交者必须确认：

- 自己运营该书源，或已经获得书源运营者授权；
- 书源只分发原创、公共领域或已获授权的内容；
- 提供的测试查询适合自动检查，并具有足够稳定性；
- 维护者会处理安全、可用性和内容权利报告；
- Manifest 中不包含秘密、Cookie 或私有基础设施信息。

## 审核

自动化验证只是审核证据，不能代替最终决定。审核者可以要求提交者证明控制权、补充授权信息、
提供源代码地址或公开举报渠道，或进行保护用户和基础设施所必需的修改。

拒绝或推迟收录时，应给出具体的协议、安全、维护或政策理由。对不同阅读器和书源必须使用
相同标准。

书源 ID 在本目录内必须唯一；自动验证会拒绝与已收录条目重复的 ID。重新使用曾被收录
书源的 ID 时，按维护权转移处理，需要提供下文所述的证明，而不是当作新提交审核。

## 维护权转移

现有维护者可以通过 PR 增加维护者或转移维护责任。如果所有维护者都无法联系，新运营者必须
证明自己控制发现接口或书源域名。只有逻辑上的同一书源继续运营时，才能保留原有稳定 ID。

## 运行状态

- `verified`：当前兼容性和政策检查通过；
- `degraded`：存在部分失败，但核心阅读链路仍可使用；
- `offline`：连续检查无法访问或使用；
- `unmaintained`：维护者没有在公开的审核期限内回应；
- `suspended`：因安全、滥用或权利问题处于调查或警告状态；
- `removed`：不再由活动目录分发。

除紧急风险外，不应因为一次检查失败就删除书源。连续失败应先标记为 `degraded`，之后再标记
为 `offline`。恢复收录时，应使用与新书源相同的验证流程。

## 紧急暂停

出现凭据泄露、恶意内容、不安全重定向、客户端利用、可信版权投诉或故意规避目录检查时，
维护者可以立即暂停书源。公开说明不得泄露秘密，也不得增加用户风险。

## 申诉

书源维护者可以通过新的 PR 或 Issue 提供修正和证据。在有其他审核者可参与时，申诉应尽量
由最初作出主观判断以外的人复核。
